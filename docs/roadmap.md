# 产品 roadmap

**exocortex 给领域 researcher 提供方向 insight：基于持续收录的工作做深度挖掘，指出下一个值得做的方向与未解决的问题；它不是又一份行业简报。** 由两个 agent 共用一个中立的证据层（`wiki/`）完成：collector agent 持续收录新且好的 idea，insight agent 写判断。前提是默认无人值守，human 只定方向、只撤销；现在离这个前提最远，所以先做它。

设计理由与已知缺口见 [design.md](design.md)。下文的数字目标是起点，由 human 定稿。

## 现在还不是 agentic-ready

每一次收录都要 human 在对话里开口，几处判断仍等人。

| human 现在要做的 | 目标 |
|---|---|
| 说「收录 inbox」「feed 收录」才会收录 | 每天定时无头运行，开 PR，收录类 PR 照旧自动合并 |
| 批准 / 并入 / 否决每个候选 lens | agent 直接建，human 撤销；这会改掉 design.md 里唯一的事前人工门，先看 agent 建的 lens 被撤销的比例 |
| 逐条处置搜索候选 | 过质量门的直接收录，human 撤销；门比 feed 严，因为搜索结果没有人的动作背书 |
| 核对 LLM 写的数字（实际没人做） | 收录后由另一个 agent 抽查关键数字是否与原文一致，不一致的退回重写 |
| feed 的浏览器 cookie 过期后手动更换 | 默认改用不需要 cookie 的官方接口，见下文「feed 的来源」 |
| 维护运行 feed 的私有机器与 cron | 换到任何能跑定时任务的地方（如 GitHub Actions），私有数据仍不进仓库 |

代码、规则、workflow 的改动仍由 human 合并，这一项不变。

## insight agent：给 researcher 的方向判断

**用户**：做某个方向的 researcher，想知道这个方向卡在哪、下一步值得做什么。第一个方向是 agentic robotics。

**为什么要持续收录**：领域迭代越来越快，判断要跟着新的好 idea 更新；收一批经典工作就停，判断很快过时。

- **写什么**：HTML 页面上每个方向一节：下一个值得做的方向与未解决的问题，各最多 3 条。每条判断链到支撑它的来源页，证据只有自报或评测已饱和时写明。
- **和证据层的分工**：来源页与 lens 总结保持中立，只记事实；判断只出现在 insight 一节，由 human 署名，agent 起草、human 改。
- **什么算高质量来源**：带来新的研究 idea 或方向的工作；实验细节多不等于高质量。
- **验收**：先服务 human：human 读完，指出至少一条「原先不知道且值得试」（agentic robotics 一节 2026-10-22 已过，接受 3 条方向）。其他 researcher 愿意读是加分，不作验收。

### 写得更好：生成与查新

现在一页 insight 是单次写成，质量靠 LLM 自评，而 LLM 自评偏高（`wiki/sources/agent-laboratory.md`）。

- **候选池加两两排序**：先生成 15–20 条候选方向，两两比较排序，留前 3 条，借 AI co-scientist 的锦标赛做法。
- **查新**：每条方向保留前搜一遍是否已有人做（借 AI Scientist 的 Semantic Scholar 查新），只保证库里没人做不够。

### collector 要收到什么

- **判定标准**：LLM 按库的目的判一个工作值不值得收，即能不能成为方向 insight 的证据或启发；human 的 star 与标注只帮它了解关心什么，不设新颖性比对、lens 范围、排除清单这类硬门。
- **立场、综述、演讲**：要有自己的来源页格式（作者、主张、预测、与哪些工作相悖），现有格式围绕评测数字写。
- **后期再做：X、LinkedIn**。领域里的人在这两处写的方向性判断是 insight 的直接输入；X 官方 API 收费、cookie 抓取脆弱，LinkedIn 没有公开 feed 接口。
- **后期再做：负面结果**。证明某条路走不通的工作、复现失败、反驳性评测；现在库里 0 篇，也没有一条「相悖」关系。它们很少上热门，feed 抓不到，需要专门的渠道。

## 引擎：agent 维护的研究 wiki

**用户**：想让 agent 替自己长期维护某个研究方向资料的独立开发者或研究者。

**定位**：NotebookLM、Zotero 加 AI 插件这类工具帮你读你收集好的文档；exocortex 替你收集，并持续维护一个方向的现状：有哪些工作、在什么评测上报了多少、是自报还是第三方复评、彼此怎么关联，存成你自己拥有的 markdown 与 git 历史。

- **规则与内容分开**：引擎（`AGENTS.md`、`scripts/`、`feed/`）与内容（`wiki/`、`inbox/`）拆开，用的人拿到的是空库，不用先删别人的 48 个来源。
- **规则短到能被照做**：去重、校验、合并这类不需要判断的步骤全部下沉进脚本，`AGENTS.md` 只留需要判断的部分，从 159 行压到 80 行以内；英文。
- **不依赖私有机器的上手路径**：定时任务、key 放在仓库 secrets，一条命令跑一次收录；不绑定 Cursor，Claude Code、Codex CLI 等无头 agent 都能跑。
- **每条收录的 token 开销可见**，用的人能判断值不值。

### feed 的来源

feed 是和普通 RSS 订阅拉开差距的那部分，而它现在依赖浏览器 cookie 读 GitHub 的非公开接口：别人复制不了，也处在服务条款的灰色地带。

- **默认**：改用官方 API（用 token 取关注者的公开事件），不需要 cookie，可以放进定时任务。代价是延迟与漏项：逐人拉事件的一次实测里，16 对「关注者 → 仓库」命中 14 对，漏掉的 2 对都是新建仓库。
- **可选**：cookie 读 feed 留作自托管用户的高级选项，不进默认上手路径。
- **决定依据**：同一天两种来源并排跑，官方 API 覆盖 feed 的 90% 以上就切为默认；不到就保留 cookie 为默认，并在文档里写明风险。

**验收**：一个陌生人只看 README，从零跑出第一份自动合并的收录 PR，两周后定时任务仍开着。

## 顺序

1. **collector 无人值守**：每天定时无头收录，开 PR、自动合并，逐次记账。已在跑，观察连续 7 天零介入。
2. **insight agent**：agentic robotics 一节已上线，human 读后接受 3 条方向。
3. **collector 的输入**：判定改为「值不值得收」已完成；下一步是立场、综述、演讲的来源页格式。
4. **insight 写得更好**：候选池与查新，扩到其它已批准 lens。
5. **引擎模板化**：流程稳定后再把规则与内容拆开、压短 `AGENTS.md`、写上手路径，避免拆完又改。

负面结果、抽查 agent、feed 换官方 API 排在这之后，需要时再拿起。

## 衡量

| 指标 | 目标 |
|---|---|
| human 每周介入次数 | 只剩「删 X」、改 insight 与 lens 范围句 |
| 撤销比例 | 收录后被「删 X」的比例，看趋势，不设门 |
| insight 有用 | human 读后指出至少一条「原先不知道且值得试」；其他 researcher 读是加分 |
| 模型开销 | 判定与收录逐次记账；每月目标 ≤ ¥20，上限 ¥40 |

## 不做

- 行业简报、每周 digest：很多人在做，只列「最近出了什么」不给方向判断。
- 托管服务、多用户账号。
- 覆盖所有领域的通用论文推荐。
- 重新引入逐条人工预审。
